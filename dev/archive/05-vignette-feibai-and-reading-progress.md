# 暗角几何、飞白墨色、朱印阅读进度

> 记录于 2026-09-10。本次是「用户报障 → 查出真根因」的一组修复，外加一个新交互（朱印承载阅读进度）。三件事的共同点是：**表面症状都指向不了真正的原因**——暗角"没效果"不是浓度问题而是几何问题；飞白"形状不对"其实墨色也反了。文中数据均为实测或实算，不是估计。

## 一、暗角"换了之后没有效果"

### 现象

背景面板里切到「暗角」，和「噪点」看不出差别。

### 根因（实算）

原渐变的椭圆半径取的是**视口的百分比当半径**（不是直径），圆心在 50%/35%：

```css
background: radial-gradient(ellipse 130% 95% at 50% 35%, transparent 60%, var(--vignette) 100%);
```

把视口角点代入归一化椭圆方程 `sqrt((dx/rx)² + (dy/ry)²)`：

| 位置 | 落在渐变的 | 后果 |
|---|---|---|
| 左上角 | 53% | `transparent` 到 60% 才结束 → **整个没着色** |
| 右下角 | 78% | 过渡区只走了 46%，乘 0.06 alpha → **实际压暗 2.8%** |
| 上边中点 | 37% | 同样在透明区 |

**视口有一大半压根落不进过渡区。** 这解释了为什么调 alpha 没用——不是不够浓，是根本没画上去。

### 修复

- 几何：`ellipse 78% 78% at 50% 42%, transparent 35%`
  → 四角 0.13–0.18、边中点 0.05–0.11、中心 0（圆心略偏上，保住「纸从上方受光」）
- 浓度：`--vignette` 亮色 0.06 → 0.18；暗色 0.16 → 0.40
- 新增 `--vignette-swatch`（亮 0.38 / 暗 0.55）。样张是 44px 见方，用页面浓度等于看不见，
  所以**有意放大**；但原先它硬编码 rgba、和页面各改各的，是个维护陷阱，现在两者并排放在 token.css
- 打印：`@media print` 里补 `html[data-bg="noise-vignette"] body::after { display: none !important }`。
  打印块那句 `background: #fff !important` 管不到固定定位的 `body::after` 遮罩，不加这条会印出一圈灰晕

`z-index: 0`（压在正文之上）保持不变——光线衰减本就同时作用于字，且 0.18 只在最角落。

## 二、飞白：形状是「断笔」，墨色还反了

### 现象

用户报「飞白线条本身形状不对」。

### 根因（两个独立缺陷）

1. **墨色反了。** 飞白没有自己的 `background-color`，于是继承了基础 `.post-content hr` 的
   `--hr-ink-strong`（alpha 0.8），成了四式中**最浓**的一条。可枯笔落墨最少，该是最淡的。
2. **形状是断笔，不是飞白。** 四条互不相连的 path，段长 51/85/67/52、缝宽 6–10、厚度恒 2–3px。
   注释承诺的「笔画渐细」没兑现；更关键的是缺了飞白的本体——**笔画内部**的纵向露白。

### 修复

- 新增 `--hr-ink-feibai`（亮 `rgba(90,75,50,0.38)` / 暗 `rgba(220,210,188,0.34)`），四式里最淡
- mask 改为「一条连续笔身（中段约 4.3px、两端收尖）+ `fill-rule="evenodd"` 挖三条不等长纵丝
  （72 / 76 / 50），y 位置错开」。同一套写法主题里已有先例——「一笔」也是靠 evenodd 挖洞
- `.swatch-hr-feibai` 不再用 `repeating-linear-gradient` 画等距断续的赝品，改为 `::before`
  复用**同一条 mask**，样张 = 实物。走 `::before` 是因为 mask 会连 `.swatch` 的纸底一起蒙掉

### 遗留

`一笔 / 断栏 / 墨点` 三条样张有同类的「样张与实物脱钩」问题，本次未动。

## 三、朱印承载阅读进度（新交互）

### 最终形态

| 状态 | 印面 | 进度指示 | 按钮栈 |
|---|---|---|---|
| 收起（默认） | 站名首字 | 印面外一圈**方框**，随进度描边填充 | 3 个 |
| 展开 | 站名首字 | 隐去（回到纯朱印） | 4 个，末位是进度读数 |

### 迭代过两版，记下为什么

1. **圆环 → 方框。** 初版是 `<circle>` 圆环，用户反馈「太蠢」——**印本来就是方的（方印）**，
   圆环跟形制不对路。改 `<rect>`，`rx=1.5` 对应印面的 `border-radius: 2px`。
   顺带甩掉 `rotate(-90deg)`：`<rect>` 天然从左上角起、顺时针走，这正是边框式进度该有的读法。
2. **卡片 → 读数。** 初版点「进度」弹一张卡片显示百分比。用户要求直接显示。
   现在按钮栈末位就是读数，卡片、`#post-progress-card`、`showCard` 的分支、i18n 的
   `toolbarProgressRead` 一并删掉。

### 实现要点

- **不能用 `pathLength="100"` 归一化。** 初版圆环靠它省掉算 `2πr`；但 `pathLength` 对基本图形
  是 SVG2 扩展，**浏览器支持不齐**，一旦不认，`stroke-dasharray` 就按用户单位解，整个进度错位。
  改成自己算：`4×(48−2×1.5) + 2π×1.5 = 189.4248`（已用脚本核对），存成 `--seal-perimeter`。
  于是 `stroke-dashoffset: calc(var(--seal-perimeter) * (1 - var(--seal-progress) / 100))`
- 读数用 `<span>` 而非 `<button>`：它是**指示**不是**控件**，没有可点的动作。
  CSS 把 `cursor` 与悬停浮起都关掉，免得给出可点的暗示。百分号是纯装饰，走 `::after`
- 方框 48×48 rx1.5、描边 2.5px（占距中心 22.75–25.25px），印面半宽 20px，留 2.75px 空隙；
  SVG `inset: -8px` **绝对定位**——留在流里会变成 grid 子项，破坏 `.post-seal` 的 `place-items: center`
- 进度以 `.post-content` 为界，不是整页——页脚和上下篇导航不该计入
- 滚动节流到 `requestAnimationFrame`，且**只在整数百分比变化时写 DOM**
- 正文图片无固定尺寸，`offsetHeight` 随解码变化，所以 `load` 和 `resize` 都要重新 `measure()`
- `.post-toolbar.is-open` 由 JS 在展开时同步，CSS 据此隐去方框

## 四、顺带：牛皮纸色收口成 token

浮动工具条、分享卡片、悬停提示三处**各自硬编码**了同一组牛皮纸色值（`#F0E5CC` / `#4A3A22` /
`rgba(140,100,45,.30)` 及其暗色版），违反「颜色只走 token.css」的约定。

新增 `--paper-tool` / `--paper-tool-ink` / `--paper-tool-line`（亮暗各一套），三处一并改用。
**值与字面量完全相同，零视觉变化**——这一步是纯粹的去重，不承担任何视觉风险。

- `hugo` 构建通过，无 warn

- 周长算式脚本核对：189.4248 ≈ CSS 里写的 189.42；`dashoffset` 在 0% / 42% / 100%
  分别为 189.42 / 109.87 / 0，符合预期
